## O que é o FeeEngine

O `FeeEngine` é uma **função pura**: recebe inputs e retorna o breakdown sem efeitos colaterais. É a única fonte da verdade para qualquer valor monetário no sistema.

<Info>
**Segurança:** o frontend nunca envia valores monetários. Ele envia apenas `registrationId`, `method`, `couponCode` e `installments`. O backend busca preços e taxas diretamente do banco e calcula tudo via FeeEngine.
</Info>

## Campos retornados

| Campo | Descrição |
|-------|-----------|
| `payerTotalCents` | Total cobrado do atleta — o que aparece no checkout |
| `organizerNetCents` | Valor que o organizador recebe após todas as taxas |
| `platformFeeCents` | Valor da taxa da plataforma |
| `gatewayFeeCents` | Valor da taxa do gateway |
| `effectiveBaseCents` | Preço após desconto do cupom |
| `discountCents` | Desconto aplicado |

## Algoritmo de cálculo

```javascript filename="fee-engine (pseudocódigo)" lines
// 1. Aplicar cupom
effectiveBase = max(0, precoBase − desconto)

// 2. Caminho FREE — sem pagamento
if (effectiveBase == 0 && !chargeFeesAnyway)
  return { payerTotal: 0, status: COURTESY }

// 3. Base para cálculo de taxas
feeCalcBase = (feeBase == PRE_DISCOUNT) ? precoBase : effectiveBase

// 4. Taxa de plataforma (Fp) — depende do platformFeeMode
// ABSORB:        payer = feeCalcBase           orgNet = effectiveBase − Fp
// PASS_TO_PAYER: payer = feeCalcBase + Fp      orgNet = effectiveBase
// FREE_WITH_FEE: payer = Fp (só taxas)         orgNet = 0

// 5. Gross-up para cartão
netNoAnt   = (anticipation > 0) ? payer / (1 − anticipation) : payer
payerTotal = ceil((netNoAnt + gatewayFixed) / (1 − gatewayPercent))
gatewayFee = payerTotal − payer
```

## platformFeeMode — Quem absorve a taxa

<Tabs>
  <Tab title="ABSORB — Organizador absorve" icon="building">
    O atleta paga o valor efetivo. A taxa da plataforma sai do repasse ao organizador.

    ```
    payer  = effectiveBase
    orgNet = effectiveBase − Fp
    ```

    **Exemplo:** Base R$50 · Fp R$5
    - Atleta paga **R$50,00**
    - Organizador recebe **R$45,00**

    <Note>É o modo padrão (`DEFAULT_PLATFORM_FEE_MODE=ABSORB`). O atleta não vê a taxa.</Note>
  </Tab>
  <Tab title="PASS_TO_PAYER — Repassa ao atleta" icon="user">
    A taxa é somada ao que o atleta paga. O organizador recebe o valor base cheio.

    ```
    payer  = effectiveBase + Fp
    orgNet = effectiveBase
    ```

    **Exemplo:** Base R$50 · Fp R$5
    - Atleta paga **R$55,00**
    - Organizador recebe **R$50,00**

    <Note>A taxa aparece no checkout detalhado como "Taxa de serviço".</Note>
  </Tab>
</Tabs>

## feeBase — Onde a taxa incide

<Tabs>
  <Tab title="POST_DISCOUNT (padrão)" icon="circle-check">
    A taxa incide sobre o preço **já com o desconto** do cupom.

    ```
    feeCalcBase = effectiveBase  (após cupom)
    ```

    O cupom reduz tanto o valor base quanto as taxas calculadas.

    **Exemplo:** Base R$100 · Cupom 20% · Taxa 5% (PASS_TO_PAYER)
    - effectiveBase = R$80,00
    - Fp = R$4,00 (5% de R$80)
    - Atleta paga **R$84,00**
  </Tab>
  <Tab title="PRE_DISCOUNT (especial)" icon="triangle-exclamation">
    A taxa incide sobre o preço **original, antes do cupom**.

    ```
    feeCalcBase = precoBase  (antes do cupom)
    ```

    O cupom reduz apenas o `orgNet` — o total do atleta não muda.

    **Exemplo:** Base R$100 · Cupom 20% · Taxa 5% (PASS_TO_PAYER)
    - feeCalcBase = R$100,00
    - Fp = R$5,00 (5% do preço original)
    - Atleta paga **R$105,00** (igual a sem cupom!)
    - Diferença do cupom absorvida pelo organizador

    <Warning>Use apenas quando o organizador quiser subsidiar o desconto do seu próprio repasse sem alterar o preço cobrado ao atleta.</Warning>
  </Tab>
</Tabs>

## Parcelamento — limite por valor

Gateways de cartão costumam exigir um **valor mínimo por parcela**. O sistema calcula automaticamente o número máximo de parcelas viável para cada valor total com base nessa regra. O limite exato é definido por cada gateway através do método `maxInstallmentsForAmount()` da interface `PaymentGatewayPort`.

**Exemplo** (valor mínimo de R$5,00 por parcela):

| Parcelas | Valor por parcela (base R$17,21) | Disponível? |
|----------|----------------------------------|-------------|
| 1× | R$17,21 | ✅ |
| 2× | R$8,61 | ✅ |
| 3× | R$5,74 | ✅ |
| 4× | R$4,30 | ❌ abaixo do mínimo |

O sistema aplica esse limite em dois momentos:

1. **`previewPaymentBreakdown`** — retorna erro para parcelas inválidas; o frontend recebe `null` e **esconde a opção automaticamente** no seletor de parcelamento.
2. **Gateway `initiate`** — capa `maxInstallmentCount` ao valor real antes de enviar ao gateway, mesmo que o chamador passe um número maior.

## Gross-up para cartão

No cartão, o gross-up garante que — após o gateway deduzir sua taxa — a plataforma receba exatamente o `expectedNetCents` alvo:

```
netNoAnt   = (anticipation > 0) ? payer / (1 − anticipation) : payer
payerTotal = ceil((netNoAnt + gatewayFixed) / (1 − gatewayPercent))
gatewayFee = payerTotal − payer
```

**Exemplo prático (gateway 3,49% + R$0,49, sem antecipação):**

```
payer alvo (PASS_TO_PAYER, base R$50 + Fp R$5,50) = R$55,50

netNoAnt   = 5550                       (sem antecipação)
payerTotal = ceil((5550 + 49) / 0,9651) = ceil(5803,6) = R$58,04
gatewayFee = 5804 − 5550               = R$2,54
```

## Configuração por evento

Cada evento pode ter regras próprias via `PaymentMethodConfig` + `PaymentFeeRule`. Se não houver configuração, o sistema usa os defaults de variáveis de ambiente.

<Tabs>
  <Tab title="Campos configuráveis">
    | Campo | O que define |
    |-------|-------------|
    | `method` | `PIX` ou `CREDIT_CARD` |
    | `gateway` | Identificador do gateway (ex: `woovi`, `asaas`) |
    | `platformFeeMode` | `ABSORB` ou `PASS_TO_PAYER` |
    | `platformFeeCents` | Taxa fixa em centavos (`0` = usa `planRate` do evento) |
    | `gatewayPercent` | % do gateway (ex: `3.49`) |
    | `gatewayFixedCents` | Taxa fixa do gateway em centavos (ex: `49`) |
    | `anticipationPercent` | % de antecipação. `0` = sem antecipação |
    | `feeBase` | `POST_DISCOUNT` (padrão) ou `PRE_DISCOUNT` |
    | `settlementHoldDays` | Dias de hold antes de liberar para saque |
  </Tab>
  <Tab title="Defaults (env vars)">
    | Variável | Valor padrão |
    |----------|-------------|
    | `PIX_PAYMENT_GATEWAY` | gateway padrão para PIX |
    | `CARD_PAYMENT_GATEWAY` | gateway padrão para cartão |
    | `DEFAULT_PLATFORM_FEE_MODE` | `ABSORB` |
    | `DEFAULT_GATEWAY_FEE_BASE` | `POST_DISCOUNT` |
    | `CARD_DEFAULT_MAX_INSTALLMENTS` | `1` |
    | `CARD_DEFAULT_ANTICIPATION_PERCENT` | `0` |
    | `CARD_DEFAULT_SETTLEMENT_HOLD_DAYS` | `32` |

    <Check>Eventos sem configuração no banco se comportam exatamente como antes — nenhuma migração necessária.</Check>
  </Tab>
</Tabs>

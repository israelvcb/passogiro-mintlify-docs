## Tipos de cupom

O sistema suporta quatro tipos, definidos pelo campo `discountType` do modelo `EventCoupon`:

<CardGroup cols={2}>
  <Card title="PERCENT — Desconto percentual">
    Desconta uma porcentagem do preço base.

    ```
    Base R$50 · Cupom 15%
    Desconto = R$7,50
    Atleta paga R$42,50 + taxas
    ```
  </Card>
  <Card title="FIXED — Desconto valor fixo">
    Desconta um valor fixo em reais do preço base.

    ```
    Base R$50 · Cupom R$25
    Desconto = R$25,00
    Atleta paga R$25,00 + taxas
    ```
  </Card>
  <Card title="FREE — Cortesia total">
    Inscrição 100% gratuita. Nenhum valor cobrado, nenhuma taxa.

    ```
    Base R$50 · Cupom FREE
    Total = R$0,00
    Status da inscrição: COURTESY
    ```
  </Card>
  <Card title="FREE_WITH_FEE — Cortesia com taxa">
    Inscrição gratuita, mas o atleta paga somente as taxas (plataforma + gateway).

    ```
    Base R$50 · Cupom FREE_WITH_FEE
    Mercadoria = R$0
    Taxa serviço = R$4,70 · Taxa gateway = R$0,80
    Atleta paga R$5,50
    ```
  </Card>
</CardGroup>

<Warning>
**FREE vs FREE_WITH_FEE:** `FREE` zera tudo — nenhum pagamento é gerado, a inscrição é confirmada imediatamente como COURTESY. `FREE_WITH_FEE` ainda cria um pagamento real cujo valor é a soma das taxas configuradas para o evento (`platformFee + gatewayFee`).
</Warning>

## Campos do cupom

| Campo | Tipo | Descrição |
|-------|------|-----------|
| `code` | String | Código único (case-insensitive na entrada) |
| `discountType` | Enum | `PERCENT` · `FIXED` · `FREE` · `FREE_WITH_FEE` |
| `discountPercent` | Decimal | Ex: `15.00` = 15% (usado no tipo PERCENT) |
| `discountValue` | Decimal | Valor em centavos (usado no tipo FIXED) |
| `maxUses` | Int? | Limite total de usos. Nulo = ilimitado |
| `maxUsesPerUser` | Int? | Limite de usos por usuário |
| `allowedCpfs` | String[] | CPFs autorizados. Vazio = qualquer atleta |
| `expiresAt` | DateTime? | Data de expiração. Nulo = sem expiração |
| `usedCount` | Int | Total de usos confirmados (incrementado no webhook de pagamento) |

## Validações aplicadas em `resolvePaymentCoupon()`

Antes de aplicar qualquer desconto, o backend valida todas as regras:

| Verificação | Quando falha | Resultado |
|-------------|-------------|-----------|
| Cupom existe | Código não encontrado | Cupom inválido ou expirado |
| Cupom ativo | `isActive = false` | Cupom inativo |
| Pertence ao evento | `eventId` diferente | Cupom não válido para este evento |
| Não expirou | `expiresAt < agora` | Cupom expirado |
| Limite global | `usedCount ≥ maxUses` | Cupom esgotado |
| Limite por usuário | Usuário já usou `maxUsesPerUser` vezes | Limite atingido para este usuário |
| Restrição de CPF | `allowedCpfs` preenchido e CPF do atleta não está na lista | CPF não autorizado para este cupom |

<Info>
**Restrição por CPF:** o CPF verificado é o `registration.athleteCPF` — o CPF do atleta inscrito. Se um responsável estiver inscrevendo um dependente, é o CPF do dependente que é verificado, não o do responsável.
</Info>

## Consumo de cotas (`usedCount`)

O `usedCount` **só é incrementado quando o webhook confirma o pagamento** — não no momento de gerar o PIX nem de abrir o checkout. Assim, cupons não são "consumidos" por pagamentos abandonados.

```
Atleta aplica cupom → armazenado na inscrição (usedCount não muda)
Atleta paga → webhook chega → usedCount + 1
Inscrição expira sem pagar → usedCount NÃO incrementa
```

---

## Como o desconto afeta o cálculo

O desconto reduz o `effectiveBase`, sobre o qual as taxas são recalculadas (quando `feeBase = POST_DISCOUNT`, que é o padrão):

```
effectiveBase = max(0, precoBase − desconto)
```

Para detalhes sobre `feeBase` e `platformFeeMode`, veja [Taxas e Cálculos](/sistema/taxas-calculos).

---

## Impacto financeiro por tipo

| Tipo de cupom | Atleta paga | Organizador recebe |
|---------------|-------------|-------------------|
| PERCENT / FIXED | `effectiveBase` + taxas (conforme modo) | `effectiveBase` − taxa plataforma (modo ABSORB) ou `effectiveBase` (modo PASS_TO_PAYER) |
| FREE | R$0,00 | R$0,00 |
| FREE_WITH_FEE | `platformFee + gatewayFee` | R$0,00 |
